# favTube

Publish a ranked top ten of your favorite YouTube videos as a public profile. Others can browse profiles, follow you, and leave feedback on your list.

Built with Next.js (App Router), Prisma + Neon Postgres, and better-auth.

## Setup

The app needs external credentials before it will run. Copy `.env.example` to `.env` and fill in:

| Variable | Where it comes from |
| --- | --- |
| `DATABASE_URL` | Neon **pooled** connection string (host contains `-pooler`) |
| `DIRECT_URL` | Neon **direct** connection string — used only by `prisma migrate` |
| `BETTER_AUTH_SECRET` | Any random 32+ byte string |
| `BETTER_AUTH_URL` | `http://localhost:3000` in development |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google Cloud Console → OAuth 2.0 Web Client |
| `YOUTUBE_API_KEY` | Google Cloud Console → enable "YouTube Data API v3" → API key |
| `NEXT_PUBLIC_APP_URL` | `http://localhost:3000` in development |

One-time external setup:

1. Create a Neon project and copy both connection strings.
2. In Google Cloud Console, configure the OAuth consent screen and create a Web Client ID with redirect URI `http://localhost:3000/api/auth/callback/google`.
3. In the same project, enable **YouTube Data API v3** and create an API key.

Then create the database tables:

```bash
npx prisma migrate dev --name init
```

And start the app:

```bash
pnpm dev
```

## Architecture notes

- `prisma/schema.prisma` — better-auth's tables (`User`/`Session`/`Account`/`Verification`) are generated by `npx @better-auth/cli generate`; the app-domain models (`VideoEntry`, `Follow`, `Comment`, `CommentLike`) are hand-written below them.
- `src/lib/prisma.ts` — Prisma client using the Neon serverless driver adapter, cached on `globalThis` so dev hot-reloads don't exhaust the connection pool.
- `src/lib/actions/` — server actions grouped by domain. Every mutation re-checks the session and resource ownership; hiding a button in the UI is not treated as a security boundary.
- `src/lib/youtube.ts` — parses watch/`youtu.be`/`shorts`/`embed`/`live` URLs and fetches title, channel, thumbnail, and duration once at add-time. Video metadata is persisted, so rendering a profile never calls the YouTube API.
- Top-ten ranks are kept contiguous (1..N) and unique per user via a `@@unique([userId, rank])` index. Reorder and delete both renumber in a two-pass transaction (park rows at negative ranks, then assign final ranks) so the unique index can't collide mid-update.
